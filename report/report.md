## 三、实验整体逻辑分析

### 3.1 本章的逻辑主线

本实验的关键不是“能进入异常处理函数”，而是处理后仍能正确继续被打断的程序。
硬件只保存少量控制状态，不会替软件保存全部整数寄存器，也不会自动换好内核栈。
因此实验按以下顺序构成闭环：

```text
正常执行
   │ 中断或同步异常
   ▼
硬件设置 sepc/scause/sstatus，转到 stvec
   ▼
__alltraps → SAVE_ALL → a0 = sp → trap(tf)
                                      │
                   ┌──────────────────┴─────────────────┐
                   ▼                                    ▼
        interrupt_handler(tf)                 exception_handler(tf)
        重设时钟、计数、输出                    分类、诊断、调整返回位置
                   └──────────────────┬─────────────────┘
                                      ▼
                 __trapret → RESTORE_ALL → sret
                                      ▼
                               恢复原执行流
```

异步中断不需要跳过原程序指令；非法指令与断点则必须跳过已处理的触发指令，
否则 `sret` 会再次执行它，形成异常循环。

## 四、实验内容与实现

### 4.1 功能模块一：Trap 上下文恢复与入口

**负责人：** 龙李宽-2413077。

**实现位置：** `code/kern/trap/trapentry.S` 中的 `RESTORE_ALL`、`__alltraps`。

#### 数据布局与调用关系

`SAVE_ALL` 在当前内核栈上分配 `36 × REGBYTES`，本次 RV64 共 288 字节：

| 槽位 | 内容 | 恢复时的处理 |
|---|---|---|
| 0 | `x0` | 恒为零，无须写回 |
| 1 | `ra` | 恢复被打断代码的返回地址 |
| 2 | 原始 `sp` | 从 `sscratch` 间接保存，必须最后恢复 |
| 3—31 | 其他整数寄存器 | 对应原槽位恢复 |
| 32 | `sstatus` | 写回控制与状态寄存器（Control and Status Register, CSR） |
| 33 | `sepc` | 写回处理函数可能修改的返回位置 |
| 34、35 | `stval`、`scause` | 保留供诊断，不需要写回来完成返回 |

`__alltraps` 执行 `SAVE_ALL` 后，将当前 `sp` 放入 `a0`，符合 RISC-V
调用约定（calling convention）的第一个参数规则，再调用 `trap(tf)`。
C 函数返回后沿同一路径进入 `__trapret`。

恢复过程先使用临时寄存器装载并写回 `sstatus`、`sepc`，然后恢复整数寄存器。
`sp` 必须最后装载：若提前恢复，它将不再指向陷阱帧，后续所有栈偏移都会错误。
288 字节也是 16 的整数倍，不破坏进入 C 函数所需的栈对齐。

`sret` 根据保存的 `SPP` 返回监督态，并通过 `SPIE` 恢复中断使能；
不是简单地执行普通函数的 `ret`。软件不需要重新打开 SIE 才能返回。

#### 最终提示词与规格

完整工作提示词保存在 [prompt.md](prompt.md) 的 Module 1。本模块按四段组织：

- **[PROMPT]**：只完成入口与恢复，保留已有保存逻辑和公开接口。
- **[RELY]**：提供实际的 36 槽布局，特别说明槽 2 是中断前的 `sp`。
- **[GUARANTEE]**：交付 `RESTORE_ALL`、`__alltraps`、`__trapret` 返回路径。
- **[SPECIFICATION]**：C 收到真实帧地址，帧中的返回状态被采用，全部可写整数
  寄存器恢复，最后恢复 `sp`，不添加已取消的 Challenge。

#### 实现迭代

上下文恢复实现首次整机验证即通过了课程寄存器测试。构建时发现框架沿用旧 CSR
名称 `sbadaddr`，新汇编器报 `unknown CSR 'sbadaddr'`。在文件开头将它映射为
同一 CSR 的现行名称 `stval`，保留 `SAVE_ALL` 的指令文本和帧布局不变。

### 4.2 功能模块二：中断与异常处理

**负责人：** 王艺霖-2410824。

**实现位置：** `code/kern/trap/trap.c` 中的
`interrupt_handler(struct trapframe *tf)`、`exception_handler(struct trapframe *tf)`。

#### 中断处理

从 `cause` 中移除最高位中断标记后，根据原因码分类。监督态时钟中断按以下顺序处理：

1. 调用 `clock_set_next_event()`，安排下一次中断。
2. `ticks` 增加一次。
3. 每达到 `TICK_NUM=100` 的整数倍，调用原有 `print_ticks()`。
4. 输出次数达到 `SHUTDOWN_AFTER=10` 时调用 `sbi_shutdown()`。

骨架没有定义指导书提到的 `SHUTDOWN_AFTER`，因此本次补充为十次报告，即
1000 次时钟中断后关机。`clock.c` 的周期为 100000 个时间基准计数，在 QEMU
10 MHz 时间基准下约为 10 ms；正常运行约十秒后完成关机。

其他已识别的软件、时钟、外部中断输出类型提示。未知中断输出原因码及完整陷阱帧。
这保留了诊断信息，没有虚构未实现设备的确认或恢复流程。

#### 异常处理

非法指令和断点分别输出类型及 `tf->epc` 地址。两者共用指令长度判断：

```c
uint16_t instruction = *(const uint16_t *)tf->epc;
tf->epc += (instruction & 3) == 3 ? 4 : 2;
```

在本实验的 RV64GC 指令集范围内，低两位不为 `11` 的指令占 2 字节，否则占
4 字节。压缩指令扩展（Compressed Extension）中的 `C.EBREAK` 和普通 `EBREAK`
虽然触发同一异常原因，但长度不同，因此不能单纯按异常类型固定加 2 或加 4。
当前内核代码映射可读，可以从触发指令的首个半字读取长度。

其他异常调用 `print_trapframe(tf)`，不擅自改变返回位置。这里完成的是实验要求的
诊断，不是页故障恢复或通用的指令模拟。

#### 最终提示词与规格

完整提示词在 [prompt.md](prompt.md) 的 Module 2：

- **[PROMPT]**：补齐两个处理函数，使用框架提供的时钟、输出和关机接口。
- **[RELY]**：列出实际的 `IRQ_*`、`CAUSE_*`、`ticks` 和相关函数。
- **[GUARANTEE]**：保持处理函数签名和已有 `trap.c` 函数不变。
- **[SPECIFICATION]**：明确下一次时钟事件、单次计数、输出周期与关机条件；
  明确异常返回位置必须根据实际指令编码前进，其他原因输出完整帧。

## 六、实验总结与收获

### 6.1 与操作系统原理的对应

| 实验知识点 | 对应原理 | 本实验中的具体体现 |
|---|---|---|
| 上下文保存／恢复 | 中断对被打断代码应尽量透明 | 任意时刻被打断，全部整数寄存器仍需保持，不仅是 C 的被调用者保存寄存器 |
| 中断与异常分类 | 异步事件与同步故障 | 时钟不跳过原指令；已处理的非法指令和断点需要跳过 |
| 特权状态恢复 | 硬件与内核分工 | 软件恢复 CSR，`sret` 根据 SPP、SPIE 完成返回 |
| 定时中断 | 时间管理与抢占的基础 | 每次安排下一事件；本实验没有进一步实现调度 |
| 临界区 | 共享数据更新期间的中断控制 | 页分配接口关闭并按原状态恢复本 hart 的中断 |
| 地址空间建立 | 物理地址与虚拟地址的转换 | 开启分页不自动改变 PC，启动阶段必须显式过渡 |

本实验未覆盖多核同步、进程调度、用户栈切换、系统调用完整生命周期、缺页恢复及
外部设备驱动。它建立了这些机制以后可以依赖的内核中断处理基础。

### 6.2 AI 协作开发的经验

1. 汇编任务的规格首先应明确帧布局和恢复顺序，而不是仅写“恢复全部寄存器”。
2. 不能把异常原因码等同于指令长度；使用统一编码判断可以消除特殊分支。
3. 编译成功不足以说明整机可用。OpenSBI 交接、开启分页后的取指、Trap 返回
   和最终关机必须连成真实运行旅程检查。
4. 复用 Lab2 时保留 Lab3 的中断保护，按接口衔接，而不是整文件覆盖。
5. 提示词、实际输出、测试副本和普通提交内核分开保存，方便复现与讲解。
